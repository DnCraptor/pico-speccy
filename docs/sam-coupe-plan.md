# SAM Coupé: анализ и план (2026-10-22, ничего не реализовано)

Источники: SimCoupe (github.com/simonowen/simcoupe, GPL-2.0+; `Base/SAM.h`,
`SAMIO.{h,cpp}`, `Memory.{h,cpp}`, `Frame.cpp`, `Events.cpp`, `CPU.h`, `Disk.h`)
и sam-users/sam-coupe-datasheets (`SAM Coupe Technical Manual v3.0.pdf`,
`WD1772`, `SAA1099`, `DS1287`/`MSM6242B`). Модель берётся из SimCoupe, как
ATM/Evo брались из Unreal: он сверен с железом (contention, interrupts, MIDI
timing), а Technical Manual подтверждает порты и режимы.

## 1. Машина в цифрах

| | SAM Coupé | для сравнения 48K |
|---|---|---|
| CPU | Z80B, **6 МГц** | 3.5 МГц |
| Строка | **384 T** (48 ячеек по 8 T; 768 hi-res пикселей) | 224 T |
| Кадр | **312 строк = 119 808 T**, 50.08 Гц | 312 строк = 69 888 T, 50.08 Гц |
| Экран | 256x192 в окне; бордюр 68 строк сверху, по 8 ячеек (64 lores px) с боков | 48 строк сверху |
| INT | кадровый в T=0 кадра, **128 T**; строчный — порт F9, `(line+68)*384`, тоже 128 T | 32 T |
| RAM | 512 КБ (32 страницы по 16 КБ; вариант 256 КБ), внешняя 1-4 МБ | |
| ROM | 32 КБ (ROM0 + ROM1), ROM 3.0, CRC32 **0B7E3585** | |
| Звук | **SAA1099** 8 МГц на `#00FF`/`#01FF` + бипер `FE` bit 4 | |
| Диск | **WD1772**, 2 дисковода, MGT 80x2x10x512 (819 200 Б) | |

Ключевое совпадение: **период кадра SAM = период кадра 48K до такта**
(119808/6e6 = 69888/3.5e6 = 19.968 мс). Значит:
- 50 Гц видеорежимы берутся 48K-шные (`[2]`, `v_total` 628 на 640x480), новой
  таблицы `video_mode` не нужно;
- аудио-набор 48K: 624 сэмпла на кадр при 31 250 Гц, и **192 T на сэмпл ровно**;
- V-Sync-пейсинг и `ESPectrum::target` — как у 48K.

## 2. Аппаратная модель (из SimCoupe)

**Порты** (декод в основном по младшему байту):

| порт | чтение | запись |
|---|---|---|
| `FE` | клавиатура: ряды по старшему байту (8 рядов), при старшем `FF` — ряд 8 (доп. клавиши + мышь); bit 5 SPEN, bit 6 EAR, bit 7 SOFF | бордюр: `bit5:bits2..0` = индекс CLUT, bit 3 MIC, bit 4 бипер, bit 7 SOFF (экран выкл. в режимах 3/4) |
| `F9` | STATUS: bits 4..0 = запросы INT (active low: line/mouse/MIDI-in/frame/MIDI-out), bits 7..5 = ещё 3 бита клавиатуры по старшему байту | LINE: строка строчного прерывания (≥192 = выкл.) |
| `FA` | LMPR | LMPR: bits 4..0 страница A, b5 ROM0 off, b6 ROM1 on в D, b7 защита записи A |
| `FB` | HMPR | HMPR: bits 4..0 страница C, b6..5 цвета mode 3, b7 внешняя память в C/D |
| `FC` | VMPR (b7 = MIDI RX) | VMPR: bits 4..0 страница экрана, b6..5 режим 1-4 |
| `F8` | LPEN (позиция луча), `1F8` HPEN | CLUT: старший байт = номер регистра 0..15, значение = цвет 0..127 |
| `FF` | ATTR (байт атрибута под лучом) | SAA1099 data; `1FF` — SAA адрес |
| `80`/`81` | | LEPR/HEPR — внешние страницы в C/D |
| `E0-E7`, `F0-F7` | WD1772 дисковода 1/2 (A0-A1 регистр, A2 сторона) | |
| `FD` | MIDI | MIDI (320 мкс на байт) |
| `EF` | часы SAMBUS (`< FE00`) / Dallas (`>= FE00`) | |
| `E8-EB` | принтер / DAC | |
| `7C-7F` | Blue Alpha sampler | SAMVox / Paula (4-канальный DAC) |
| `1F` | Kempston | |

**Страничная адресация** (`UpdatePaging`): A = ROM0, если LMPR.b5 = 0, иначе
LMPR; B = LMPR+1; C = HMPR (или EXT+LEPR при HMPR.b7); D = HMPR+1, ROM1 при
LMPR.b6, EXT+HEPR при HMPR.b7. Номера по модулю 32. Защита записи только A.

**Режимы экрана** (страница VMPR, для 3/4 — пара `page & ~1`, 24 КБ):
1. ZX-раскладка (6912 Б), атрибуты 8x8, ink/paper → CLUT 0..15;
2. линейный битмап 32 Б/строку + атрибут на байт по `+0x2000`;
3. **512x192, 4 цвета** (2 бита/пиксель, 128 Б/строку), цвета 1-2 из HMPR b6..5;
4. 256x192, 16 цветов, 4 бита/пиксель, 128 Б/строку.

Цвета: CLUT 16 регистров, каждый — индекс 7-битной палитры (128 цветов, G/R/B
по 2 бита + общий bright).

**Contention** (самое важное для скорости и демо): перед КАЖДЫМ циклом памяти
к **внутренней RAM** (не ROM, не внешней) `wait = mask - ((t + 2) & mask)`,
`mask` = 7 в области экрана в режимах 2-4 (и в режиме 1 ещё в чередующихся
64-тактовых полосах строки), иначе 3; при SOFF в режимах 3/4 — 3 везде.
Порты ASIC (`>= F8`) — всегда `mask` 7. `t` = позиция в кадре со смещением
`+4` для строки. Ожидание вставляется **в начале** цикла, а не после.

**Прерывания**: кадровое — 128 T в начале кадра; строчное — 128 T в начале
строки `line+68`. Регистр маски нет; `STATUS` отражает активные запросы.
ASIC «спит» первые ~49 мс после включения (порты `>= F8` читаются 0).

## 3. Как это ложится на прошивку

SAM — **не Spectrum**: ни одного общего порта ULA, другая частота, другая
адресация. Ближайшие прецеденты в дереве — **TS-Conf** и **Next**: свой arch,
свой модуль в `src/speccy/machines/`, ранний выход из `Ports::input/output`,
свой рендерер строк.

### 3.1 Arch и меню
- `A_SAM` в X-macro `ArchRom.h` (APPEND, на диске — имя), romset `R_SAM30`.
- Machine → новая строка **SAM Coupé** (или Machine → Other — вопрос владельцу).
- Гейт `p_showSam` = VGA_HDMI + butter PSRAM ≥ 1 МБ + `FlashRoms::romsUsable()`
  (как TS-Conf): 512 КБ страниц должны быть pointer-backed, а режиму 3 нужен
  pair-драйвер.
- Переход в/из SAM — всегда **перезагрузка** (`Config::wantedPages(A_SAM)` = 32,
  +64 при внешних 1 МБ; раскладка страниц решается один раз в setup()).
- Исключения (resolveConstraints + MachineSwitch + CPU::reset, как обычно):
  Beta-128, esxDOS/DivMMC, MB-02+, IDE-схемы ZX, GS/NeoGS, AY/TurboSound/TSFM,
  Timex, ULA+, 16col, Gigascreen, Covox-порты, ZiFi NIC (`#xxEF` = порт часов
  SAM), Murmuzavr. SAA1099 принудительно ВКЛ (он на плате), Kempston оставить.

### 3.2 Модуль `src/speccy/machines/Sam/`
- `Sam.{h,cpp}` — состояние ASIC (LMPR/HMPR/VMPR/LEPR/HEPR/border/line/status/
  CLUT), `Sam::remap()` = **единственный писатель** `MemESP::ramCurrent[]` через
  `plug16` (как `TsConf::setBanks`, `Atm::remap`), `Sam::portRead/portWrite`
  (flash, `noinline`), reset, power-on fill (SimCoupe: `0xFF` с полосами `0x00`
  по 128 Б — заполнять через `powerOnRamFill` для целевой машины).
- Вход в Ports: самая первая проверка `if (Z80Ops::isSam) return Sam::port…`
  — одна проверка флага в RAM-функции, тело во flash (правило «машинный код вне
  общих RAM-путей»). Если PERF покажет, что опрос клавиатуры/ASIC стоит
  заметно — окно `.samovl` по шаблону `.ftovl`/`.ngsovl`.
- ROM: 32 КБ raw во flash (`tools/rom_pack.py sam`, CRC в `rom_verify.py`).
  Оверлеев не будет — базы не похожи. Защита записи A — через существующий
  гейт `g_atm_ro` (бит окна 0), ROM-окна и так read-only по указателю.
  Лицензия: ROM 3.0 распространяется с разрешения Andy Wright (так в SimCoupe);
  код — портирование семантики GPL-2.0+ в GPL-3.0, совместимо.

### 3.3 Такты и прерывания
- `CPU::statesInFrame` 119 808, `IntStart` 0 / `IntEnd` 128, без `<< multiplicator`.
- Строчное прерывание — второй источник, как LINE у TS-Conf: `isActiveINT` =
  кадровое окно ИЛИ окно строки; кадр в срезах до следующего события
  (`nextIntEvent`, «Stage D»), HALT спит до события (`haltAdvanceTo`).
- **Contention**: новый бит в `g_memgates` (memcyc, рядом с DRAM-моделью
  TS-Conf) → холодный путь `Sam::memWait(t, slot)` в `Z80Ops::peek8/poke8/
  peek16/poke16` и в ОБОИХ местах выборки опкода (`fetchOpcode` и
  `exec_nocheck` — урок Timex). Ожидание считается от `CPU::tstates` ДО
  добавления тактов цикла. Слот «внутренняя RAM» — флаг в `ramContended[]`,
  который выставляет `Sam::remap`. Ожидания на I/O к `>= F8` — в
  `Sam::portRead/Write`. Стоимость: ~1-1.5 обращения на такт × 6 МГц через
  холодный вызов — оценка 5-10% core0 при 378 МГц; мерить PERF_HIST.
- Без contention BASIC/игры будут работать на ~25-35% быстрее — для фазы 1
  допустимо, для демо нет.

### 3.4 Видео
- Рендерер целых строк `SamVideo` (flash, при необходимости — в окно), такт по
  шаблону `tsDrawTick`/`atmDrawTick`: строка рисуется в конце своей бумаги,
  fast-путь памяти (`g_ts_fastmem`) возможен только БЕЗ contention — значит,
  обычный путь доступа + счётчик строк.
- Окно fb 320x240: 256 бумаги + по 32 lores px бордюра, сверху 24 строки
  (бумага на fb-строке 24, как 48K); 360x288 — 52 px бокового и 48 сверху.
- Цвета: 16 регистров CLUT → аппаратные слоты 0..15 (`samPalette[128]` →
  RGB888 через `paletteFinal`), как gpal у TS-Conf. Режимы 1/2/4 пишут в fb
  индекс CLUT напрямую.
- **Режим 3 (512 px) = pair-драйвер** (Profi DS80 / GMX / Timex hi-res):
  байт fb = `profi_pair_lookup[l][r]` над 16 цветами CLUT — ровно та ёмкость,
  что у Timex. Вход/выход только в vblank (`samVideoApplyPending` в EndFrame
  рядом с `gmxApplyPending`); смешанный кадр (режим 3 на части строк) —
  как Demorama у TS-Conf: кадр целиком в pair-режиме, lores-строки — диагональ
  пары. TFT/SOFTTV — левый пиксель пары (как Timex fallback).
- Gigascreen выключается режимом (`gigascreenModeIncompatible`), бордюр-полосы
  — `gmxBorderFrame`-подобная заливка с построчным повтором (`tsBandRow`).
- Фаза 2: эффекты внутри строки — кольцо {T, старое значение} для бордюра и
  CLUT (как `NEXTVID::borderMark`), SOFF, VMPR посреди строки
  (`ModeArtefact`/`BorderArtefact` SimCoupe — можно не делать).

### 3.5 Клавиатура, мышь, звук
- Матрица 9x8 + 3 бита в F9. PC → SAM: F0..F9 (функц. клавиши SAM — на F1..F10
  уже заняты хоткеями; выход — режим «клавиши гостю», как PS/2 у TS-Conf: ON/
  OFF/AUTO или Alt+цифры), EDIT, DELETE, INV, CNTRL, SYMBOL, курсоры.
- Мышь SAM — на `FE` со старшим `FF` (полубайтовый протокол) — фаза 3.
- SAA1099: существующий `SAASound` уже декодирует `#00FF/#01FF` (одиночный чип
  Karabas) — подключить для SAM. Бипер — бит 4 `FE`.
- SAMVox/Paula (`7C-7F`) — через микшер Covox, фаза 3.

### 3.6 Диск
- WD1772 ≈ наш WD1793 (нет READY, бит motor-on/spin-up). Нужен адаптер портов:
  выбор дисковода по базе порта (`E0`/`F0`), сторона по A2 — в обход Beta-SYS
  `#FF` (у WD1793-модуля нужен API «выбрать drive/side»).
- Форматы: **MGT** (плоский, 80x2x10x512, иногда 9 секторов = DOS 720K) —
  основной; SAD (заголовок + плоские секторы); EDSK через `DskImage` (тот же
  секторный уровень, что у +3). MGT/SAD в `wd1793` проще всего добавить как
  «плоский образ с геометрией» поверх существующего пути 512-байтных секторов
  (Profi CP/M уже ходит 512/1024).
- Автозапуск: F5/Web на `.mgt` → смонтировать в A:, сброс, затем инжект F9
  (BOOT в ROM 3.0) по шаблону `plus3AutoBootArm`.
- Слоты дисков, F8-лампа, `DISK_*`-тип файлов в браузере.

### 3.7 Лента и прочее
- Лента в реальном времени: длительности TAP/TZX — в тактах 3.5 МГц, для SAM
  умножать на 12/7 (в `Tape::Read`, рядом с хуком износа). Быстрая загрузка —
  ловушки ROM 3.0 по образцам SimCoupe (`LDSTRT`, `EDGLP`, `LOADEXIT`), позже.
- Снимки: стандартного формата нет → блок в `.pss` (фаза 4).
- Внешняя RAM 1-4 МБ (LEPR/HEPR), часы SAMBUS/Dallas (`EF`) через `RTC::`,
  Atom Lite IDE (`.hdf`), MIDI `FD`, light pen — фаза 4, по запросу.

|---|---|---|

## 5. Оценка стоимости
- Flash: ROM 32 КБ + код ~40-60 КБ (во flash или в окне).
- Статическая SRAM: цель ~0 (состояние ASIC — на куче при входе в машину,
  код — flash/окно); RAM страниц — butter PSRAM (512 КБ, +1 МБ внешней).
- Хост: 6 МГц ≈ 1.7x 48K, в разы легче TS-Conf 14 МГц; основная нагрузка —
  contention-путь и рендер строки (режимы 3/4 читают 128 Б/строку из PSRAM).

## 6. Риски
1. **Модель contention в нашем ядре**: оно прибавляет такты после доступа,
   SAM требует ожидание в начале цикла. Решение — считать ожидание от
   `tstates` до `+3/+4`, проверять трассой против SimCoupe, а не на глаз.
2. **CLUT-эффекты по строкам**: однострочный рендерер + глобальная палитра
   даёт TS-Conf-подобную проблему «палитра vs луч»; фаза 1 — применять CLUT
   по лучу (`tsPalettePoll`-схема), фаза 4 — сегменты внутри строки.
3. **WD1772 через WD1793-модуль**: он заточен под Beta (SYS `#FF`, TRD-трапы);
   нужен чистый API выбора дисковода/стороны, без поломки Beta/Profi/Scorpion.
4. Хоткеи F1..F12 против функциональных клавиш SAM.

## 7. Вопросы владельцу
1. Где в меню: отдельная строка «SAM Coupé» или Machine → Other?
2. 512 КБ по умолчанию; внешняя RAM — нужна сразу или потом?
3. Только платы с butter PSRAM (как TS-Conf) — ок?
4. Приоритет: диск (MGT — основной формат софта) раньше ленты — ок?
5. Функциональные клавиши SAM: режим «клавиши гостю» как у TS-Conf (ON/OFF/AUTO)
   или фиксированное сопоставление (например, Alt+0..9)?
